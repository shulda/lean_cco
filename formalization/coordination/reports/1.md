## M1 — Actual public representations

The initial public interface lives in the `CCO` namespace. The root
`CCO.lean` imports **every** implementation/consumer module, so both
`lake build` and the transitive `CCO` audit cover the entire export
closure. There is no external EPPA/Ramsey repository dependency.

- `CCO.TypedRelation`: `TRel X i j = X i → X j → Prop`. Its
  `ident` uses real equality; `top` is all actual pairs; `comp`
  uses genuine intermediate witnesses, including coinciding endpoints.
- `CCO.Atomic`: `AtomicSource ι X` with finite named sorts, nonempty
  real carriers and finite typed diversity palettes `S.Atom i j`.
  Actual pairs are `Sigma X`; `S.colour x y : Option (S.Atom i j)`
  is `none` **iff those actual tagged points are equal**.
  Same-sort atoms are symmetric; cross-sort converse is typed and
  involutive; every diversity atom has real witnesses.
  `S.Menu i j = Set (S.Atom i j)` NEVER contains fake identities.
- `CCO.Supports`, `CCO.PairHomogeneity`, `CCO.ActionBridge`:
  `rawSupport` and `representedSupport` identify invariant
  equality-inclusive represented relations with their occurring optional
  atomic colours. `PairHomogeneous`, `ColourInvariant` and pair-orbital
  identification are derived from actual `HomogeneousSource`, not postulated
  as global additional axioms.
- `CCO.RawWords`: typed `RawWord` with a true empty loop word,
  erasable equality *letters*, reversal and concatenation.
  `CCO.PositiveWords`: a nonempty diversity-only word,
  actual represented relation and STRONG profile; `CCO.RawStrongBridge`
  contains the diversity guard and precise two-step RAW/STRONG conversion.
- `CCO.Finite`: finite **complete** actual induced structures and
  induced embeddings, plus finite **partial** specified-diversity diagrams,
  `DiagramHom` (collisions permitted), and
  `DiagramHom.IsInjective` (all tagged images distinct).
  `HomogeneousSource` (finite complete original-source homogeneity),
  `AgeSAP` (actual finite induced strong amalgamation) and
  `SemanticCCO` (homomorphic cycles criterion) are separate interfaces.
  No CCO completion theorem is claimed or used in B001.
- `CCO.GroupActions` uses actual group actions and kernels, not chosen
  quotient sections or formal abstract orbital symbols. A single compatible
  action on all `X i` induces the action on `Sigma X`.

The proposed decisions for later workers are recorded as D008–D012 in
